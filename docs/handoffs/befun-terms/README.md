# BEFUN 이용약관 초안 반영

2026-10-16 작성. 사용자 요청은 `/terms`의 임시 안내를 BEFUN 맞춤 가구 서비스에 맞는 이용약관으로 교체하는 것이다. 작성·화면 구현은 완료했으며, 운영 정보와 시행일을 확인하기 전까지는 **검토용 초안**이다. 법률 전문가의 개별 검토나 공정위 인증을 받은 문서로 표시하지 않는다.

## 변경 범위

- `src/components/storefront/legal/terms.ts`: 6개 주제, 24개 조항의 단일 원문과 확인된 운영자 정보.
- `src/components/storefront/legal/TermsPage.tsx`: 핵심 안내 3개, 조항별 본문, 데스크톱 목차, 모바일 펼침 목차, 운영자·이메일 안내.
- `src/components/storefront/legal/terms.module.css`: 페이지 전용 반응형·인쇄 스타일, 헤더와 겹치지 않는 여백, 앵커 스크롤 여백.
- `src/app/(storefront)/terms/page.tsx`: 기존 catch-all보다 우선하는 전용 경로. 기존 공통 Header/Footer 재사용. 초안은 검색 색인 제외.

기존 `PolicyPage` 및 다른 정책, 개인정보 처리방침, 배송 페이지, 계정·주문·결제 API는 변경하지 않았다. 약관 열람 페이지를 구현한 것이며 약관 동의 기록, 법정 주문 취소나 반품 자동화까지 구현한 것으로 해석하면 안 된다.

## 본문에 반영한 기준

- 디자인 저장·공유·장바구니와 구매계약을 구분한다. 주문한 최종 사양과 이후 저장 디자인을 구분하고, 제작 중 사양 변경은 별도 합의하도록 한다.
- 제작·배송 일정과 배송·설치 비용은 주문 전에 안내한다. 코드에 들어 있는 금액이나 외국 브랜드의 정책을 BEFUN의 확정된 운영 약속으로 전용하지 않았다.
- 주문 제작이라는 명칭만으로 단순변심 청약철회를 일괄 배제하지 않는다. 개별 생산, 회복할 수 없는 중대한 피해 예상, 거래별 사전 별도 고지 및 서면·전자문서 동의 요건을 모두 확인하도록 한다.
- 하자·사양 불일치에 관한 권리와 일반 청약철회를 분리했다. 법정 청약철회에 포장비·취소 수수료 같은 위약금을 부과하지 않는다.
- 일반 철회 7일, 계약과 다른 이행에 관한 3개월 및 발견·발견 가능 시점부터 30일, 반품 수령 또는 미공급 철회 시점부터 3영업일 환급을 반영했다. 3개월과 30일의 관계는 법제처 20-0108의 해석도 확인했다. 하자담보 등 다른 권리는 별도로 남는다.
- 개인정보 선택 동의, 마케팅 동의를 약관 동의와 분리한다. 게시물·디자인 권리를 이용자에게서 일괄 양도받거나 광고 사용권으로 확대하지 않는다.
- 회사의 고의·중과실 등 법정 책임을 면제하지 않고, 소비자 거주지에 따른 법정 관할을 보존한다.

## 운영자가 확정해야 할 정보

사용자에게 비동기 질의를 보냈으나 작성 시점에 답변을 받지 못했다. 아래 항목은 임의로 만들지 않았다.

1. 법인명·대표자·현재 영업소 주소의 최종 확인, 사업자등록번호와 통신판매업 신고번호.
2. 고객센터 전화번호·운영시간, 실제 수신 가능한 고객지원 이메일, 반품·교환 주소.
3. 컬렉션별 주문 사양 확정·제작 시작 시점, 변경 가능 단계, 실제 제작·배송 소요 기간.
4. 배송 가능 지역, 설치 포함 범위, 추가 현장 비용, 반품 운송비 산정 기준과 비용표.
5. 상품별 품질보증·수리 기준, 유상 수리 비용 기준, 원자재 특성·허용 오차·안전 안내.
6. 시행일과 기존 이용자에 대한 적용·통지 계획.

현재 회사 정보는 기존 `StorefrontFrame.tsx`의 footer에서 확인한 `(주)유에이블 코퍼레이션 / 이진수 / 서울시 강남구 언주로 97길 7, 5F / contact@befun.co.kr`이다. 과거 외부 기업 소개에 다른 주소가 있었지만 현재 정보라고 판단하지 않아 반영하지 않았다.

## 실제 주문 흐름과 확정 전 필요한 연결

읽은 흐름: `/order` → `POST /api/orders`(결제 대기 주문·사양 저장) → Toss 결제 → `POST /api/payment/confirm` → 결제 완료. 약관은 결제 대기 주문번호 발급과 회사의 주문 승낙을 구분한다. 최종 운영 기준을 정할 때 결제 확인·승낙 통지 시점과 제작 착수 기준을 실제 알림·상태 처리에 맞춰 점검해야 한다.

아래는 이번 문서·화면 구현의 완료 여부와 별개인 운영 연결 과제이다.

- 회원가입/결제 시 적용 약관 버전, 동의 시점, 중요 조건 확인을 기록하는 절차.
- 청약철회를 제한할 주문에 한한 별도 고지·전자문서 동의와 해당 사양·제작 단계의 증거 보관. 일반 약관 체크만으로 대체 불가.
- 취소·반품 요청 접수 및 상태 관리, 법정 기한 내 환급·PG 취소, 주문 승낙·배송 변경 개별 통지.
- `/contact`는 현재 문의 내용을 파일로 저장하는 화면으로 실제 접수가 아니다. 약관에서는 기존 footer 이메일을 직접 안내했다. 수신함이 실제 운영되는지 확인해야 한다.
- `/privacy_policy`, `/shipping` 등 별도 안내가 여전히 임시 상태다. 실제 운영과 수탁·보유 현황을 확인하여 별도 확정해야 한다.
- 위 연결과 운영 정보가 갖춰지기 전에는 초안 표시·시행일 미정·noindex를 유지한다. 이를 해제할 때 법률 검토와 실제 흐름의 정합성도 확인하는 것이 바람직하다.

## 커밋·푸시 검증 · 2026-10-16

사용자의 명시적인 커밋·푸시 요청으로 최신 원격 main `d280fbf` 기준 독립 사본 `/private/tmp/befun-terms-publish-20261016`을 준비했다. 게시 범위는 이용약관 소스 4개, 이 인계 문서, 해당 작업의 team-tasks 기록뿐이다. 공유 작업 폴더의 다른 변경이나 Git index는 사용하지 않았다.

- 게시 소스 4개는 앞서 검증한 원문·화면 스냅샷과 SHA256이 일치한다.
- 동시 번역 작업이 공유 `/terms/page.tsx`에 추가한 `localizedMetadata`는 최신 원격에 아직 없는 export를 사용한다. 게시 사본은 원래 검증된 정적 metadata 선언을 유지하며, 공유 폴더의 번역 변경은 보존했다.
- 게시 사본 전체 lint: 오류 0 / 기존 경고 13. 소스 scoped lint도 PASS.
- 게시 사본 production webpack build·TypeScript·라우트 생성 PASS, `/terms` 생성 확인. 첫 시도는 샌드박스 Google Fonts DNS 조회 제한으로 실패했으며, 허용된 네트워크 환경에서 다시 실행해 성공했다. 코드나 폰트를 우회 수정하지 않았다.
- 초안 표시·시행일 미정·noindex는 그대로 유지한다. 약관 동의/취소·환급 API와 다른 정책 페이지는 이 커밋에 포함하지 않는다.
