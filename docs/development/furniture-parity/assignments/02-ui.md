# 왼쪽2 · Claude UI — 실제 선반 상태 연결 / R2.1-UI

## 이번 작업의 결과

이미 구현한 FurniturePanel이 fixture가 아닌 **현재 선반 상태를 읽고 실제 기존 편집 동작을 실행**하도록 연결한다. 높이·스타일의 기존 동작을 조용히 바꾸지 않는다. 옷장 UI는 보존하고, 옷장 생성기의 공백을 일반 선반으로 대체하지 않는다.

당신은 claude-optimizer였던 Claude UI 세션이다. 49개 preview 검사와 핫스팟 작업을 다시 만드는 것이 이번 과제가 아니다.

## R2 지시의 오류 정정

이전 지시의 ‘높이를 setHeight로 연결’은 철회한다. 실제 `DimensionPanel.tsx`는 **1~10 행 개수**를 조절하며 기존 rowHeights를 유지하고 새 행을 32cm로 채운다. 높이는 판 두께와 각 행 높이로 계산한다. store의 setHeight는 38~228cm clamp 및 별도 행 계산을 거쳐 다른 결과를 낸다.

또한 `StyleSelector.tsx`의 현 동작은 setStyle 후 hardware.reset이다. 이것이 Tylko와 같은지는 리더의 별도 판단 대상이다. 새 패널만 reset을 생략하면 같은 옵션이 두 곳에서 다르게 작동한다. 이번에는 기존 효과를 한 함수로 모아 일관성을 유지하고, 보존 정책 변경은 독립 이슈로 보고한다.

## 파일 소유권과 좁은 예외

- 신규 소유: `src/components/ui/furniture-panels/legacy/{LegacyShelfPanel.tsx,view.ts,actions.ts,...검사}`.
- 기존 본인 파일: `furniture-panels/index.ts`의 export.
- **이번에 추가 위임:** `src/components/ui/DimensionPanel.tsx`의 행 수 handler 추출·호출만, `src/components/ui/StyleSelector.tsx`의 스타일 handler 추출·호출만. CSS/마크업/모바일 레이아웃은 보존한다. 이 좁은 로직 변경은 리더가 위임하며 기존 graphics 레이아웃 소유권은 유지한다.
- `src/stores/**`와 공통 types, 실제 page 마운트, 가격·생성기는 리더 소유다. store 파일은 편집하지 않는다.
- handoff: `docs/handoffs/claude-1-ui.md`, 캡처 `docs/handoffs/assets/claude-1-ui/r2/**`.

## 구현 지점과 순서

### 1. 현재 동작을 함수로 공유한다

`legacy/actions.ts`에 현재 DimensionPanel/StyleSelector의 handler를 옮긴다. 다음 호출 이름을 공개한다(신규 계약이며 아직 존재하는 함수라는 뜻은 아니다).

- `setLegacyRowCount(count: number): void`
- `setLegacyStyle(style: StyleType): void`
- `applyLegacyShelfIntent(intent: FurnitureEditIntent): { applied: boolean; reason?: string }`

행 수 처리: 유효한 정수 1~10, 기존 rowHeights 복사, 부족할 때만 32 추가, `height = thickness + Σ(rowHeight + thickness)`. 현재와 같이 rowHeights/numRows/height 세 필드만 **한 번에** setState하고 reconcileHardware를 호출한다. 이는 기존 handler 추출을 위한 좁은 setState 예외이며 전체 store 교체 허용이 아니다. 줄인 뒤 다시 늘릴 때 기존 보관 행 높이를 유지하는 현 동작도 보존한다.

스타일 처리: 지원 목록 확인 후 기존 setStyle/reset 효과를 공유한다. 동일 스타일 재선택에서 기존 버튼과 새 버튼의 차이를 명시하고, 새로운 데이터 삭제를 추가하지 않는다. 기존 재선택 reset을 개선하려면 별도 사례와 리더 판단을 요청한다.

### 2. 실제 값으로 view를 만든다

`legacy/view.ts`에 순수 view 생성 함수를 두고 필요한 store 값만 받는다. `LegacyShelfPanel`은 Zustand 상태를 구독하고 이 함수를 사용한다. 매 렌더 새 객체 selector 때문에 무한 렌더가 생기지 않게 한다.

| control ID | 표시·선택 | 실행 |
|---|---|---|
| `legacy.style` | Pattern/Grid/Slant/Mosaic/Pixel/Gradient, 기존 아이콘 순서 | setLegacyStyle |
| `legacy.density` | 0~100, 현재 운영 slider의 step 재사용 | setDensity |
| `legacy.width` | 30~450cm, step1 | setWidth |
| `legacy.rowCount` | value=1~10 행 수, 표시값은 현재 totalHeight cm | setLegacyRowCount |
| `legacy.depth` | 24/32/40cm만 | setDepth |
| `legacy.backPanel` | 기존 ON/OFF 의미의 choice | setHasBackPanel |

현재 표시 높이의 조절발 +1cm는 `DimensionPanel`과 동일하게 유지한다. 이는 Tylko의 실제 노출 높이를 확정한 것이 아니다. footHeight 교정은 리더 후속이다. view의 panelProfileId는 `befun-legacy-shelf`; 원본 제품군 전체를 지원한다고 표시하지 않는다.

이번 범위에 포함되지 않은 색상/마감·행 개별 편집·문/서랍·접합·옷장 항목은 기존 운영 UI로 유지한다. 리더가 마운트할 때 이 여섯 제어만 교체할 수 있도록 컴포넌트를 분리한다.

### 3. intent 검증

허용 control ID + kind=set + global target + 값 타입을 확인한다. density/width/rowCount는 NaN/Infinity/범위 밖 값을 거부한다. depth/style/backPanel은 명시 목록을 검사한다. 미지원 action·heightMode·section intent는 `{applied:false}`이고 상태 무변경이다. 변환은 기존 cm→표시 cm이며 새로운 mm 저장 구조는 만들지 않는다.

### 4. 리더에게 실제 마운트 단위를 넘긴다

export 경로, 교체 가능한 기존 여섯 UI, 그대로 남겨야 할 색상/가격/AR 영역을 handoff에 쓴다. 운영 page/모바일에 이미 다른 작업자 변경이 있으므로 직접 전체 패널을 덮지 않는다. 리더가 연결한 뒤 동일 화면에서 상태 연결을 재확인한다.
