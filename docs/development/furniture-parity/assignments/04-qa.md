## 두 번째: 브라우저 재현

기존 VPN Chrome을 사용한다. 먼저 현재 URL·선택·판재 수를 기록한다. 사용자 작업이 있는 탭은 새로고침하기 전에 상태를 확인하고, 같은 Chrome 내 검증용 Befun 탭을 활용한다. 공유 개발 서버를 재시작하지 않는다.

1. OVVO에서 사용자 구멍/슬롯을 편집 UI로 추가한다. 실제 입력 UI 접근이 불가능하면 그 부분을 unknown으로 기록하고 컴포넌트 검사로 대체한 범위를 명시한다.
2. clip→OVVO 왕복, 편집 값과 ID/개수를 확인한다.
3. clip 상태에서 실제 MPR 버튼 및 다른 출력 버튼을 확인한다. 함수 검사와 실제 버튼 검증을 각각 기록한다.
4. 별도 새로고침 사례: connector 선택 복구와 사용자 가공 복구를 분리한다. 사용자 가공 persistence는 최근 수정에 포함되지 않았으므로 유실되면 신규 이슈로 보고한다.
5. 검사 후 최초 설정으로 복귀한 사실을 기록한다. 자동화 timeout이면 마지막 확인 상태를 남긴다.

## 구조·시각·제조 검증을 분리

- 구조: 판재 수, 안정 ID, 접합 pair, 각 행/구획 칸 수, 가로판 분절, 도어/서랍 대상과 조절발 지지점.
- 시각: 동일 카메라/설정/viewport에서 색·부품 윤곽·치수 표기·가림 상태. 다른 초기 상태의 화면을 같은 사례로 비교하지 않는다.
- 제조: 확인된 부품/프로파일/공구 규격만. 외형 메시의 자기 일치 검사로 가공 가능을 승인하지 않는다.
- 리더가 분석에 사용하지 않은 설정을 추가 검증한다. 미확정 공차를 임의로 확대해 통과시키지 않는다.

## 보고 형식

각 사례에 `ID, 실행 시각, 코드 fingerprint, 초기 상태, 조작, 기대, 실제, 판정, 캡처, 실행 명령, 수정 담당`을 기록한다. P1(편집 손실/잘못된 제조 출력), P2(상태 잔류/잘못된 오류/형상 모순), 시각차이를 구분한다.

담당자가 수정한 뒤 **같은 실패 사례를 재실행**한다. 원본 fail 기록은 보존하고 재검증 결과를 추가한다. 독립 검증 완료와 프로젝트 전체 완료를 구별한다. 본인의 검사/로그 파일 잠금은 해당 차수 종료 시 해제한다.
