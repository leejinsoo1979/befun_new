## 목표와 현재 상태

동일한 옵션과 필요한 초기 상태를 입력했을 때 Tylko와 같은 가구 구조가 생성되고, 제품별 우측 UI·개별 편집·외형이 대응하도록 Befun을 개선합니다. 브랜드와 사업 정책은 유지합니다. 관찰하지 않은 값을 임의로 채워 동일하다고 보고하지 않습니다.

현재 조사 범위는 11개 용도 카테고리와 34개 초기 모델 링크입니다. 활성 preset은28개 확보했고 나머지6개는 미확인입니다. 옷장14개 조작 사례를 추가했습니다. 이 숫자는 생성기 구현 완료나 모든 옵션 조합 검증을 뜻하지 않습니다. 기존 스타일 구현도 제품군별 검증 범위를 넘어 재사용하지 않습니다.

UI는 조사 근거가 구체적인 옷장 Edge/Tone 패널부터 병렬 착수할 수 있습니다. 이것이 옷장 생성기가 완성됐다는 의미는 아닙니다. 리더의 첫 통합 대상은 기존 선반의 남은 차이와 데이터 확보 상황을 확인해 인계 문서에 고정합니다. 이후 Original 낮은 수납, Desk/화장대, Vinyl, Edge 수납/옷장, Tone 각 계열을 단계적으로 연결합니다. 같은 용도/같은 이름만으로 생성기를 합치지 않습니다.

스토어프런트 실제 진입·카테고리·상품 연결은 다섯 번째 담당자가 맡고, 공통 공유 직렬화와 상태 적용 함수는 리더가 맡습니다.

각 단계가 끝나면 코드·검증·미해결 항목을 인계합니다. 다른 담당 작업이 필요해도 독립 가능한 부분은 계속 진행합니다. 미확인 값 때문에 필요한 실제 모델 구현만 대기시킵니다.

## 일관성을 유지하는 운영 규칙

- 공통 타입·생성 공식·통합 파일은 리더 한 명이 소유합니다. 다른 담당은 본인 디렉터리에서 작업합니다.
- 공통 규격 변경은 `contracts.md` 변경 이력과 모든 영향 담당자의 인계 문서에 연결합니다. 사용자의 재승인 없이 해결 가능한 기술 조율은 팀 내부에서 처리합니다.
- 데이터 흐름은 하나입니다: 사용자 입력 → 리더의 상태 전이/검증 → 생성 결과 → UI/3D/CNC/저장 어댑터. UI나 메시가 각자 가구 크기·구획·발 개수를 재계산하지 않습니다.
- `observed`와 `validated`를 구분합니다. 미구현 기능을 작동하는 UI처럼 배포하지 않습니다. preview 상태는 명확히 표시합니다.
- shared dev 서버·다른 세션의 Chrome 탭·빌드 산출물을 임의로 종료/삭제하지 않습니다. 통합 빌드는 리더가 조율합니다.
