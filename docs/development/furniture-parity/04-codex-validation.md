# 04 — Codex 검증 담당: 근거 검사·구조 비교·회귀 검증

작업 ID R1-QA. 결과는 [검증 인계](../../handoffs/codex-assistant-validation.md)에 기록합니다.

## 허용 파일

신규 `scripts/furniture-validation/**`, 이 경로 안의 독립 테스트/실행 설명, 본인 인계 문서. 제품 소스와 `docs/tylko-reference/cases/**` 원본은 읽기 전용입니다. 오류 발견 시 원본을 조용히 수정하지 말고 사례/필드/기대 근거를 보고합니다.

## 단계 A — 즉시 가능한 근거 검사

category JSON에는 모델 배열을 가진 초기 조사 파일과 개별 옷장 조작 파일이 함께 있습니다. 파일 이름만으로 동일 schema를 강제하지 말고 명시적 어댑터를 만듭니다.

- case ID 중복, URL 제품 ID와 preset ID, screenshot 파일 존재/상태, 입력 옵션·초기 상태·조작 순서, 단위·정밀도 확인.
- initial preset과 편집 후 현재 상태를 분리. 옷장 `currentInternalParameters=null`을 초기 preset으로 대체하면 안 됩니다.
- 같은 초기 제품을 참조한14개 조작 사례를14개 새 모델로 세지 않습니다.
- 로딩preview14개, 활성preset 미확인6개, 측정하지 않은geometry를 unknown으로 보고합니다. 파일이 존재한다는 이유만으로 참조 검증 pass가 되지 않습니다.
- 인증·쿠키·토큰을 새 보고서에 포함하지 않습니다. 공개 제품 필드와 관련 URL만 사용합니다.

## 단계 B — 공통 결과 계약 이후

판재/개구부/구획/문/서랍/다리 결과를 mm 좌표로 정규화한 비교 입력을 받습니다. 원본 관찰값과 Befun 생성값을 별도 파일/객체로 보존합니다. 배열 순서만으로 부품을 매칭하지 않고 안정 ID·역할·연결 관계를 활용합니다.

비교 항목: 구획 수와 토폴로지, 칸 내경, 판 중심/두께/분절, 지지 판재와 발 위치, 문·서랍의 소속 개구부와 간섭, 전체 bounds. missing/extra/unknown과 수치 오차를 분리합니다. 가려진 부품은 미측정으로 남깁니다.

분해도/CNC에서 합쳐진 통판이 남는지 실제 같은 생성 결과로 검사합니다. 최대 길이는 검증된 spec별 기준을 받고 임의로3000mm를 보편 기준으로 만들지 않습니다.

## 단계 C — 통합 검증

같은 입력/초기 상태 재생성, 값 복귀, 변경 순서, preset 전환, 구획 편집, 저장/공유/새로고침을 검증합니다. UI·3D·CNC가 서로 다른 계산을 하는지 확인합니다. 규칙을 맞추는 데 사용한 사례와 별도의 보류 사례를 구분해 보고합니다.

기존 `scripts/tylko-hardware/**`와 스타일 검증을 읽고 필요한 회귀를 연결합니다. 새 테스트 프레임워크를 설치하기보다 현재 실행 가능한 Node 도구를 사용합니다. 셸 명령·환경·결과를 기록하고 테스트 숫자가 정확한 동치 사례 숫자인 것처럼 표현하지 않습니다.

## 산출물

실행 가능한 검사 도구와 설명, 검사 자체의 meaningful pass/fail/unknown 예제, 기계 판독 결과 및 짧은 사람용 보고서, 결함별 사례 ID/우선순위/담당 제안. 구조 비교와 픽셀/재질 비교를 분리하고 오차 근거 없는 pass를 금지합니다. 제품 소스 수정은 리더에게 인계합니다.
