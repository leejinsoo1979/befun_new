# R2 실행 지시 — 2026-10-14

사용자 “지시해”에 따른 리더 배정. **이 문서가 이전 착수 지시보다 우선한다.** 완료한 미리보기·감사만 다시 보고하지 말고 아래 산출물을 구현한다. 기존 네 작업자와 리더가 기본 5인이고, 별도 조립 담당은 추가 인원이다. 화면 위치보다 역할 이름을 우선한다.

현재 상태는 **배정 게시 / 수신 미확인**이다. 각 담당자는 본인 handoff에 R2 작업 ID·세션명·착수 시각·수정 파일을 기록하고 team-tasks의 잠금을 갱신한다. 기존 변경을 보존하고 수정 직전 파일을 다시 읽는다. 실제 충돌이 있으면 해당 파일만 조율하고 독립 작업은 계속한다.

## 왼쪽1 — Claude 하드웨어·그래픽 / R2-HW

**OVVO V-1230P/R의 잘못된 단품 형상을 교정한다.** 기존 Tylko 클립 단품은 유지한다.

- 근거: `docs/tylko-reference/ovvo-implementation-audit.md`, `cases/ovvo-audit-001.json`, `sources/ovvo-audit-001-*.pdf`. 원본 도면의 정면·측면·단면을 직접 읽고 현재 Housing/Connector와 대조한다.
- 소유: 신규 `src/components/three/furniture-hardware/ovvo/**`, 본인 `docs/handoffs/claude-2-hardware.md`. 공용 index 수정이 필요하면 같은 담당이 한다. 조립 담당은 이 폴더를 수정하지 않는다.
- P의 PH/PC, R의 PH/RC/RH를 구분한다. 바깥 상자만 비슷하게 바꾸지 말고 도면에서 확인되는 비대칭·맞물림·외곽을 반영한다. 사진/도면에 없는 내부 잠금 형상은 추정 표시하고 정확한 제조 형상으로 보고하지 않는다.
- 좌표 계약을 먼저 본인 handoff에 게시한다: mm 단위, 패널 접합면 기준 원점, 삽입축/슬라이드축, 각 부품의 체결 완료 변환, 장착 포켓 기준. 이 계약을 조립 담당이 그대로 소비한다. 별도의 부품 치수표를 조립 담당에게 다시 만들게 하지 않는다.
- 근거가 없는 치수는 자료 출처와 미확정 상태를 함께 전달한다. 설명용 값은 CNC 규격으로 내보내지 않는다.
- 완료 기준: P/R별 정면·측면·단면 및 체결 전후 캡처, 도면 대비 확인/미확인 목록, 감사 001/003의 교정 결과. 알려진 캡슐 홈과 부품의 충돌을 검사하고, 실제 언더컷 윤곽이 미확정이면 그 부분은 unknown으로 남긴다. 코드 검사 통과만으로 형상 일치 완료를 선언하지 않는다.

금지 범위: Shelf/배치 공식/CNC/GuideScene. 기존 재질·조명 사용자 작업은 별도 기존 잠금으로 유지한다.

## 왼쪽2 — Claude 옵션 UI / R2-UI

**기존 선반에 한정해 미리보기 패널을 실제 Zustand 상태에 연결하는 어댑터를 구현한다.** 옷장에 기존 선반 생성기를 대신 연결하지 않는다.

- 소유: `src/components/ui/furniture-panels/legacy/**` 신규 어댑터·연결 컴포넌트·검사와 본인 handoff. 필요 시 본인 `furniture-panels/index.ts` export만 추가한다.
- 공개 입구: `LegacyShelfPanel` 컴포넌트. 실제 `useShelfStore`를 구독하여 `FurniturePanelView`를 만들고 `FurniturePanel`에 넘긴다. 상태는 fixture나 별도 persist에 복사하지 않는다.
- 최소 연결: width/height/depth/style/density/hasBackPanel. 허용값·높이 단계·선택 순서는 현재 운영 `DimensionPanel`/`StyleSelector`/관련 계산 함수에서 확인하고 재사용한다. 미리보기 fixture의 값을 운영 범위로 승격하지 않는다.
- intent는 기존 `setWidth`, `setHeight`, `setDepth`, `setStyle`, `setDensity`, `setHasBackPanel`만 호출한다. `setState`로 전체 상태를 덮거나 새 생성 규칙을 만들지 않는다. ID 화이트리스트·값 타입·유한수·선택지·global target을 확인한다. 미지원 intent는 상태를 변경하지 않는다.
- 이번 어댑터는 **legacy cm→표시 cm**이며 mm 공통 설계 상태를 새로 정의하지 않는다. 신규 제품군 mm 경계는 리더 소유다. 이 좁은 예외는 contracts.md에 게시한다.
- 완료 기준: 패널 입력이 실제 store를 바꾸고 외부 store 변경이 패널에 즉시 반영됨, 잘못된 입력/미지원 intent 무변경, 스타일·밀도 조작 시 관련 없는 색상/가공 초기화 없음, 모바일/키보드 검사. 높이·깊이에 따른 기존 store의 정당한 행/하드웨어 보정은 별도로 기록한다.
- 전달: 컴포넌트 import 경로와 실제 store 연결 검사를 handoff에 남긴다. **운영 page 마운트는 리더 담당**이며 이 단계는 ‘상태 연결 완료/운영 마운트 대기’로 보고한다. 옷장/제품군 preview 완료 기록은 유지한다.

금지 범위: `src/types/furniture.ts`, stores, 운영 page, 가격, 생성기. UI-11/12 공통 타입 요청은 별도 리더 검토 사항이며 이 어댑터의 선행 조건이 아니다.

## 왼쪽3 — Codex 쇼핑몰 연결 / R2-SAVE

**ENTRY-SAVE-004의 실제 서버 저장 오류를 수정한다.** 감사만 반복하지 않는다.

- 이번 차수의 좁은 소유권을 리더에서 이 담당에게 위임: `src/lib/db.ts`, `src/app/api/designs/route.ts`, `src/app/api/designs/[code]/route.ts`, 신규 `scripts/storefront-save-validation/**`, 본인 handoff. 리더는 이 파일을 동시에 수정하지 않는다.
- 설치된 Prisma adapter의 실제 타입/구현을 확인하여 `PrismaPg` 생성자 인수 오류를 고친다. DATABASE_URL이 없을 때 기본 로컬 DB로 몰래 연결하지 않는다.
- 환경 미설정 시 설계 저장/조회에 명확한 서비스 사용 불가 응답을 내고, import 시점 예외가 사이트 전체를 깨지 않게 한다. 기존 prisma 소비자의 호환성, 인증·소유권 확인, 입력 검증을 보존한다.
- 실제 서버 성공과 로컬 fallback을 구분한다. DB 미설정 상태에서 성공했다고 표시하지 않는다. 필요한 클라이언트 변경은 정확한 파일을 handoff에 요청하고 먼저 독립 가능한 서버 수정을 끝낸다.
- 완료 기준: 올바른 adapter 구성 검사, 환경 미설정의 예측 가능한 실패, 잘못된 입력/인증 응답 회귀, 기존 DB 소비자 타입 검사, lint/격리 build. 실제 DB가 구성되어 있으면 테스트 설계 저장→조회 왕복을 확인한다. 구성되지 않았다면 실제 DB 왕복은 blocked로 명시한다.
- `.env`/인증 정보/실제 DB/마이그레이션/주문/결제 정책은 변경하지 않는다. 로그에 연결 문자열을 출력하지 않는다.

접합 필드의 설계 저장·공유 공통 계약은 여전히 리더 책임이다. ENTRY-CONNECTOR-003의 8개 경로 감사 결과는 재사용하며 임의 스키마를 추가하지 않는다.

**OVVO 설명 화면의 잘못된 형상과 동작을 실제로 교정한다.** 미확정 안내 문구만 추가한 상태를 수정 완료로 보고하지 않는다.

- 소유: `src/components/assembly-guide/**`, `src/lib/assembly-guide/**`, `src/app/assembly-guide/**`, `docs/assembly-guide.md`. 하드웨어 `ovvo/**`와 공통 CNC는 읽기 전용.
- 즉시 가능한 작업: OVVO-AUDIT-001~003을 현재 시연에서 재현·캡처하고, P/R 단계별 부품/변환을 공식 PDF와 대조한다. 변환·시퀀스·슬롯 표시를 하드웨어 모델과 분리해 연결 준비한다.
- R2-HW의 모델/좌표 계약 게시 후 그것을 import하여 기존 상자형 Housing/Connector를 교체한다. 본인 범위에서 또 다른 OVVO 부품 모델을 만들지 않는다.
- P의 압입과 R의 삽입/슬라이드/해제를 분리한다. 공식 도면의 15mm 표기는 그 도면의 해당 동작에만 적용하고 다른 품번/클립에 일반화하지 않는다.
- 직선 캡슐 포켓을 실제 언더컷 제조 단면이라고 표시하지 않는다. 확인 가능한 윤곽을 구현하고 미확정 영역은 절개 설명 등으로 구분한다. 불가능한 간섭을 카메라/투명도로 숨기지 않는다.

하드웨어 인계 전에도 재현·시퀀스 교정은 진행 가능하다. 전체 가구/다리 조립 안내는 이 교정 후 리더 접합계획을 받아 확장하며 현재 완료로 선언하지 않는다.

## 리더 — R2-CORE

작업자에게 공통 구현 대기 책임을 돌리지 않는다. 다음 순서의 핵심 소유권을 유지한다.

1. 접합 선택을 설계 단위로 보존할 공통 상태/직렬화·복구 계약을 실제 타입과 함수로 게시한다. 누락된 기존 고객 데이터는 확인된 OVVO 규격으로 단정하지 않는다. 현재 optimizer의 legacy 기본값과 고객 설계의 미확인 상태를 구분한다.
2. 제품군 registry와 UI view/intent 적용·복구를 구현하고, 연결된 제품군만 활성화한다. R2-UI의 legacy 어댑터는 기존 선반용으로만 통합한다.
3. 옷장 Edge/Tone의 관찰 사례를 기반으로 생성기를 실제 연결한다. 구획·문·내부 구성·옵션 제약을 단계별 검증하며 기존 shelf preset으로 대체하지 않는다.
4. 판재 분절·다리 지지점·접합점의 동일 계획을 Shelf/조립/CNC가 소비하도록 실제 배치를 연결한다. HW-REQ-04 좌표 계약에 해당 접합면·축·상대 패널 ID를 제공한다.
5. OVVO 감사의 미검증 품번 자동 가공 상태를 정리하고 근거 없는 제조 규격을 확정 취급하지 않는다. 연결 후 QA 사례로 교차 확인한다.

소유: 공통 types/stores, `src/lib/furniture/**`, 공통 sharing, 생성기, Shelf/배치/connector plan/CNC, 운영 page의 실제 연결. **R2-SAVE에 위임한 db/design API, R2-UI의 legacy 어댑터는 리더가 동시에 편집하지 않는다.** graphics의 page 레이아웃/AR 잠금은 존중하여 마운트 위치를 조율한다.

## 보고와 인계

- 각 handoff에 `R2 ID / 수신 / 실제 수정 파일 / 구현 / 실제 연결 / 검사 명령·결과 / 남은 차이 / 다음 담당`을 남긴다.
- 상태는 `배정→수신→진행→검증 대기→해당 범위 완료`로 바꾼다. 막힌 경우 정확한 선행 산출물과 독립 진행 결과를 함께 적는다.
- 소스 변경은 필요한 검사·lint·격리 build를 수행한다. 공유 dev 서버 종료/공용 .next 삭제 금지. 다른 담당 실패를 자기 완료로 숨기거나 임의 수정하지 않는다.
- 모든 항목이 완료되기 전 전체 구현 완료·제조 가능·Tylko 완전 동치라고 보고하지 않는다.
