# 공통 완료·검증 기준

모든 담당자가 같은 기준을 사용합니다. 기능별로 `근거 확보 / 구현 / 연결 / 검증` 상태를 따로 기록합니다. 전체 목표 미완료인 상태에서 부분 완료를 전체 완료로 보고하지 않습니다.

## 제품군 하나의 통합 완료 조건

| 영역 | 확인할 내용 | 담당 |
|---|---|---|
| 입력/초기 상태 | 전체 옵션, 필요한 seed/편집 이력, preset 버전, 재현 순서 기록 | 리더 + 검증 |
| 우측 UI | 해당 제품군 항목·순서·값·단위·활성/비활성·조건부 표시, 선택 구획 대상 | UI + 검증 |
| 구조 | 칸 수/배치/행 높이/내경/비대칭·가장자리, 판재 분절 | 리더 + 검증 |
| 문·서랍 | 개구부 소속, 전면 간격, 내부/외부 모드, 개폐와 간섭 | 리더 + 검증 |
| 다리 | 종류·개수·좌표·앵커, 하판/세로판 지지 관계, 폭 변화 경계 | 리더 + 외형 + 검증 |
| 외형 | 판 두께·접합·하드웨어·색/재질/텍스처, 같은 시점의 비교 | 외형 + 리더 |
| 전체 흐름 | 상태·3D·치수·조립·CNC가 같은 부품 구조를 사용 | 리더 + 검증 |
| 복귀/저장 | 값 복귀, 다른 변경 순서, 다른 초기 디자인, 새로고침/공유 복구 | 리더 + 검증 |

## 필수 비교 방법

- 한 번에 한 옵션을 바꾸고 대표값·최소/최대·구조 전환 경계 전후를 기록합니다. 이어 조합과 변경 순서를 검증합니다.
- 규칙 개발에 사용하지 않은 설정을 최소 하나 이상 제품군별로 검증합니다. 한 보류 사례만 통과했다고 전체 조합을 검증한 것으로 설명하지 않습니다.
- 구조의 수/연결 관계는 정확히 비교합니다. 수치 오차는mm로, 표시 치수는 반올림/내경 여부와 함께 기록합니다.
- 시각 비교는 같은 카메라·투영·화면 크기·옵션을 맞춥니다. 원본 카메라/광원 값을 모르면 모른다고 적습니다. 로딩preview는 제외합니다.
- 지적된 결함을 수정한 뒤 동일 사례를 재실행합니다. 회귀가 있는 상태를 검증 완료로 표시하지 않습니다.

## 실행과 보고

변경에 해당하는 기존 검사와 의미 있는 새 검증을 실행합니다. 최종 통합은 lint, TypeScript/production build와 브라우저 동작 확인을 포함합니다. 현재 package.json에는 npm test가 없으므로 존재하지 않는 명령을 전제로 삼지 않습니다. shared .next 충돌은 담당자 간 빌드 시간/격리 환경으로 해결하고 다른 작업자의 산출물을 삭제하지 않습니다.

개별 UI/3D 담당은 자신의 검사 결과를 인계하고, 리더는 통합 결과를 기록합니다. 문서만 수정한 단계는 JSON/링크/규격 일관성 검사로 구분하며 제품 build를 했다고 보고하지 않습니다.

결함 기록: `ID / 사례 / 기대 근거 / 실제 결과 / 구조 또는 시각 / 수치와 단위 / 우선순위 / 담당 / 상태 / 재검증 결과`.

상태는 pass/fail/unknown/not-applicable을 구분합니다. 측정 불가, 기능 미구현, 로딩 실패, 비교 입력 부재는 pass가 아닙니다. 결과를 통과시키기 위해 reference나 허용 오차를 바꾸지 않습니다.
