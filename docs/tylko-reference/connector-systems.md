# 패널 접합 옵션 — OVVO / Tylko 클립

사용자 결정: 2026-10-13, 두 방식을 별도 옵션으로 제공한다. 다리의 잠금핀 장착부는 이 설정과 별개다.

| 항목 | OVVO 방식 | Tylko 클립 방식 |
|---|---|---|
| 내부 system ID | `ovvo` | `tylko-clip` |
| 근거/현재 범위 | 기존 OVVO 품번별 제조사 규격/플래너 | Tylko Original 공식 조립 PDF(connector-clip-003), 포럼 실물 사진 |
| 가공 | 선택 품번별 홈/보링 | 단면 매입 클립·상대 판 면의 나사 체결부 관찰. 정확한 가공 치수 미확정 |
| 조립 | P/R 등 실제 선택 품번에 따라 구분 | 해당 클립 구조 전용 동작 필요. OVVO 안내 재사용 금지 |
| 현재 구현 | 기존 경로 유지 | 방식 선택·로컬 저장·미확정 가공 차단까지 구현 |

## 관찰 근거

[사용자가 지정한 글](https://www.dasheimwerkerforum.de/threads/tylko-regal-mit-klicksystem.25990/), 2022-12-13 작성자의 첫 게시물과 첨부 사진. 작성자는 판을 끼우기 전 풀었던 나사를 다시 조이지 않아 유격과 분리 문제를 겪었다고 보고한다. 이 경험담은 제조 규격이나 공식 작업 지침이 아니다. 댓글의 강제 분리 방법을 고객 조립 절차로 채택하지 않는다.

Chrome에서 직접 본 사진: 판의 좁은 단면에 길쭉한 검정/주황 삽입 부품이 있고, 상대 판의 넓은 면에 체결부가 돌출한다. 정확한 소재·치수·나사 돌출량·잠금 이동 거리는 사진으로 측정하지 않았다. [사례 connector-clip-001](cases/connector-clip-001.json), [단면](screenshots/connector-clip-001-edge-reference.png), [상대 면](screenshots/connector-clip-001-face-reference.png).

## 이번 코드 경계

- `src/types/connectors.ts`: 두 system ID/표시명. OVVO 품번 선택과 상위 접합 방식 선택을 구분한다.
- `ConnectorSelection.system`: 기존 optimizer 데이터에 필드가 없으면 기존 OVVO 의미를 보존한다. 이것은 옛 고객 설계의 미기록 하드웨어를 실제 OVVO였다고 단정하는 규칙이 아니다.
- `/optimizer`의 `패널 접합 방식`: 두 옵션을 선택/저장한다. OVVO 선택 품번·공구번호는 복귀를 위해 보존하지만 클립 선택 중에는 가공에 사용하지 않는다.
- 클립 또는 알 수 없는 system의 제조 계산은 OVVO로 fallback하지 않는다. 이전 자체 생성 커넥터 가공을 제거하고 기존 힌지/사용자 가공은 보존하며 구조 판재를 제조 미준비로 표시한다. 클립의 실제 모델/BOM/슬롯을 임의로 생성하지 않는다.
- 현재 저장은 기존 `befun-optimizer-connectors` localStorage 범위. 고객 컨피규레이터/공유/주문 전체에 이 선택이 보존되는 연결은 아직 미완료다.

## 통합 계약과 담당

- 리더: 제품별 접합점·지지 판재 ID를 먼저 정하고, system별 부품/가공/조립 계획을 분기한다. 두 방식이 같은 구멍 위치/홈/조립 방향을 쓴다고 가정하지 않는다. 제작 규격이 확보되면 클립용 독립 플래너를 추가한다.
- Claude 하드웨어: `tylko-clip` 클립 외형과 상대 체결부를 별도 부품으로 모델링한다. 길쭉한 외형만 맞춘 임의 치수를 제조 규격으로 넘기지 않는다. 다리 브래킷과 구분한다.
- Claude UI: 리더 view가 제공하는 두 방식 표시/선택을 렌더한다. 옵션 변경으로 가구 스타일·재질을 임의 초기화하지 않는다. 판매용 적용은 실제 공통 상태 연결 이후.
- Codex storefront: 설계·공유·주문에 `system` 및 검증된 부품 규격 버전을 보존하는 공통 직렬화 계약을 소비한다. 가격 변경은 별도 결정이다.
- codex-assembly: 현재 V-1230R/P는 OVVO 내부 품번 두 종류이지 사용자 요청의 두 시스템이 아니다. Tylko 클립용 순서는 별도이며 치수/기구 검증 전 OVVO 애니메이션에 이름만 바꿔 연결하지 않는다.
- Codex QA: 방식 왕복/재로드, 이전 방식 가공 잔류, unsupported fallback, BOM·3D·조립·CNC·공유 일관성 검사. 클립 미구현 가공을 pass로 처리하지 않는다.

## 완료 조건과 남은 범위

실물 또는 치수 있는 규격에서 클립 길이/폭/깊이·고정 나사 중심/직경·상대 체결 나사 돌출량·판 두께 조건·접합 배치·결합/해제 변위를 확보해야 정확한 가공과 작동 모델을 구현할 수 있다. 현재 모두 null/미확정이다. 특정 구형 사진의 구조를 모든 Tylko 제품군에 일반화하지 않는다.

이번 회귀: 커넥터13개 + 기존 조립 예시4개 =17개 통과. 방식 분리·기존 OVVO 호환·잔류가공 제거·unknown 차단을 포함한다. 실제 Tylko 클립 구조 동치 검사가 아니다.

Chrome3003에서 옵션 전환·클립 선택 재로드 유지·OVVO 복귀를 확인하고 기존 OVVO/몸통없음/후면없음으로 복원했다. 전체 ESLint 오류0/기존경고8, 격리 스냅샷 전체 TypeScript 통과. 격리 webpack build는 Google Fonts DNS 실패 후 권한 확장 재시도에서도 next/font Google loader 파싱 오류로 실패했다. [검사 로그](../development/furniture-parity/checks/connector-systems-tests.log), [빌드 로그](../development/furniture-parity/checks/connector-systems-build.log). 상단 고객 패널·서버 공유·실제 클립 3D/CNC는 이 검증 범위에 포함되지 않는다.


## KNAPP Mod-eez 추가 근거 — connector-clip-002

사용자가 제공한 [Sets 화면](screenshots/connector-clip-002-knapp-sets-reference.png)과 [Anti-Rotation 화면](screenshots/connector-clip-002-knapp-antirotation-reference.png)을 원본으로 보존했다. [사례 JSON](cases/connector-clip-002.json).

### 확인한 원리와 구분

[제조사 설명](https://knappconnectors.com/industries/furniture-manufacturing/)에 따르면 Mod-eez는 스프링강 경사 클립과 숄더 나사가 슬라이드하면서 조여지는 은폐 접합이다. Double Clips는 숄더 나사 두 개를 사용한다. Anti-Rotation은 별도 변형이며 두 제품의 규격을 혼합하면 안 된다. [Sets 목록](https://knappconnectors.com/mod-eez-system/sets/)에는 non-locking, semi-locking, locking, pass-thru 기능과 여러 품번이 구분되어 있다.

Tylko 실물의 단면 매입 부품/상대 면 체결부 관찰과 비교할 기구 후보이다. **KNAPP가 Tylko에 납품한 제품이라는 확인이나 동일 품번 확인은 아직 없다.** 사이트의 가구 사진만으로 납품 관계를 확정하지 않는다. OVVO / Tylko 클립의 두 상위 선택지는 유지한다.

### 도면 발견과 검증 한계

- [Mod-eez Instruction Manual](https://knappconnectors.com/wp-content/uploads/2020/03/Mod-eez-Instruction-Manual-32020.pdf): 검색/문서 텍스트에서 4031/4032/4035, 2075/2076, 5075/5076 및 VERSION 03(2015-02-26)을 확인. PDF 페이지 시각 검증 요청은 404로 실패했다. 도면 관계·현행 개정·채택 품번 확인 전 숫자를 가공 상수로 옮기지 않는다.
- [4030 Series Clip Drawings](https://knappconnectors.com/wp-content/uploads/2025/08/4030-Series-Clip-Drawings.pdf): 색인 텍스트에 참고 형상과 실제 맞물림/작동 검증의 구분이 있으며 정확한 설치는 별도 설치·포켓 지침을 참조하도록 안내한다. 페이지 시각 검증은 cache miss로 실패. 외관 도면 하나로 슬롯 깊이와 조립 변위를 확정하지 않는다.
- 산업 소개의 최소 판 두께·폭은 제품군 설명이다. 개별 품번의 포켓 치수, 고정 나사, 숄더 높이 및 판재 조건을 함께 확인해야 한다. 실제 Tylko 적용 치수는 사례 JSON에서 null로 유지한다.

### 담당자 적용 지시

- 리더: 품번별 설치 도면 확보 → 기존 Tylko 사진과 대응 확인 → 홈/나사/접합면 좌표 계약 → 제조 플래너 순으로 연결한다. 32mm 같은 수치가 부품 고정 나사 간격인지, 가구 전체 접합점 간격인지 도면 기준으로 구분한다.
- Claude 하드웨어: 클립, 클립 고정 나사, 상대 숄더 나사를 분리해 표현할 구조로 설계한다. Anti-Rotation과 일반 클립의 형상을 하나로 취급하지 않는다. 현재는 참고 구조이며 임의 치수를 제조 규격으로 전달하지 않는다.
- codex-assembly: 판 접근과 경사면 체결 이동을 구분할 수 있도록 준비한다. 잠금/해제 방식은 품번별로 달라진다. 다리의 중앙 핀 해제 절차나 OVVO P/R 동작을 이 클립의 해제 절차로 재사용하지 않는다.
- QA: 품번 확정 뒤 클립 포켓·고정 나사·상대 나사·이동 여유·판 두께를 함께 검사한다. 이번 자료 추가는 실물 동일성 또는 가공 완료 판정이 아니다.


## Tylko 공식 조립 동작 확정 — connector-clip-003

사용자 제공 [원본 PDF](sources/connector-clip-003-tylko-aligning.pdf)의 13쪽 전체를 읽고 렌더링해 확인했다. [사례 JSON](cases/connector-clip-003.json). 원문 제목은 **Aligning Horizontal and Vertical Elements**, 분류는 **Assembling Your Tylko Original**, 표시된 갱신일은 2025-02-13이다. [출처 URL](https://tylko.elevio.help/en/articles/34-aligning-horizontal-and-vertical-elements). 이번 판단은 첨부 PDF 기준이며 웹 최신판과의 대조는 하지 않았다.

### 관찰로 확인한 내용

- p1–2: 검정 핀↔검정 커넥터, 은색 핀↔은색 커넥터로 맞춘다. 과거 버전은 검정/주황이며 주황↔주황으로 맞춘다. 따라서 connector-clip-001의 주황색 부품은 공식 문서가 설명하는 구형 색상과 일치한다. 이것만으로 공급사나 품번이 확정되지는 않는다.
- p2: **locking / non-locking 두 종류**가 존재한다. 이것은 OVVO / Tylko 클립이라는 Befun의 두 상위 옵션과 다른 층위다. 문서에 색상별 잠금 기능의 명시 대응은 없으므로 검정=잠금형 같은 규칙을 임의 지정하지 않는다.
- p3–4: 대응되는 핀과 단면 클립 입구를 정렬하고 접합면 쪽으로 접근한다. 그려진 접합 가장자리의 커넥터는 두 개지만 모든 깊이·제품의 개수 공식으로 일반화하지 않는다.
- p5: 핀이 들어간 다음 패널을 클립 장축 방향으로 밀어 체결한다. 도해 화살표는 아래 방향이다. p6 확대도에서 핀의 최종 위치와 판 끝선이 맞는 상태를 구분한다.
- p6–12: 가로·세로 패널 끝선이 어긋나지 않고 직각을 이루어야 한다. 필요시 펠트 보호판과 고무망치로 앞/뒤의 어긋남을 조금씩 정렬하며 아래부터 위로 진행한다. 고객 안내에는 원문의 보조 인원과 가구 고정 지침도 유지한다. 본 문서는 해체 절차를 직접 설명하지 않으므로 조립의 역재생을 해체 방법으로 확정하지 않는다.

### 구현 및 검증 계약 — 기존 KNAPP 추정보다 우선

1. 상태를 `색상 대응 → 입구 정렬 → 핀 진입 → 체결 슬라이드 → 끝선/직각 확인`으로 나눈다. 핀이 입구에 들어가기 전 슬라이드하거나, 끝선만 맞춘 상태를 잠금 완료로 표현하지 않는다.
2. 접합면 접근 방향과 클립 장축 이동 방향을 **각 접합부 로컬 좌표**로 관리한다. p5의 화면 아래 화살표를 모든 판재의 월드 Y 하강으로 복사하지 않는다. 완성 가구의 앞/뒤 정렬(p8–10)도 고려해 패널 자세에서 변환한다.
3. Claude 하드웨어: 단면 매입 클립과 상대 핀을 분리하고 색상 대응을 표현한다. 모델에 조립 전 입구/체결 후 위치를 구분할 수 있는 기준점을 마련한다. mm 치수/변위는 확정 전 제조 데이터로 제출하지 않는다.
4. codex-assembly: 위 단계를 전용 Tylko 클립 시퀀스로 구현할 근거가 확보됐다. 수치 없는 동작 시연은 설명용임을 구분하고, 정확한 이동 거리·잠금 기구·제조 규격 검증까지 완료한 것으로 표시하지 않는다. 기존 OVVO 안내와 다리 잠금핀 동작을 재사용하지 않는다.
5. 리더·QA: 같은 접합계획의 핀/입구 대응, 접근 뒤 슬라이드 순서, 최종 끝선 정렬을 검증한다. 실제 품번·홈 치수·나사 돌출량·체결 이동 거리는 이 PDF에 없으며 null을 유지한다. KNAPP 품번의 임의 대입도 금지한다.

이번 반영은 **Tylko Original 조립 절차의 직접 근거 확보 및 인계**다. 클립 3D/가공/실행 애니메이션 구현 완료가 아니다. 원본 PDF와 p2–6/p10/p12 렌더를 저장했으며 사용자 원본은 변경하지 않았다.


## 사용자 지정 실물 외형 — connector-clip-004
