# Pattern

상태: Type02/Farbe의 기본 열린 구조 생성기 교체·수치 검증 완료. Pattern 전체 옵션·시각 동치는 미완료. Befun 함수: `src/lib/three/styles/pattern.ts`.

## 이전 탐색에서 관찰한 내용 (정식 재측정 필요)

- 행별 칸 너비가 비균등하며 밀도 1% 이동에도 내경 표기가 조금씩 변한다.
- 밀도0과100 사이에 칸 수·배치뿐 아니라 가로판이 끊기고 두 행을 연결하는 78cm 개구부가 나타났다.
- 일부 행 좌/우 가장자리에12cm 표시가 있다. 닫힌 작은 칸이라고 단정할 수 없으며 열린 돌출부와 구별해야 한다.
- 450cm,38cm 한 행,깊이40에서 밀도0→1→2 탐색. 숫자가 작아 모든 칸 너비는 아직 확정 측정하지 않았다.
- 너비284.3cm,5행38,깊이40의 밀도0/39.3/100, 너비238.7cm의0/100도 탐색했으나 정확한 전체 초기 상태와 저장 스크린샷이 없어 회귀 정답으로 사용하지 않는다.

## 교체 전 Befun과 차이 (이력)

- seed를 sin으로 만들고28/45/62/75/95 후보를 뽑은 뒤 교대 ±4cm 이동한다. Tylko 근거가 없는 기존 근사식이다.
- 모든 행 경계에 전체 너비 가로판을 넣으므로 두 행 병합 개구부가 불가능하다.
- 양 끝 수직판이 항상 있어 열린 가장자리 형상이 다르다.
- 평균 panelSpacing을 하드웨어에 사용하여 비균등 개구부에 맞지 않는다.
- width≤43 분기에서 뒷판/서포트를 생성하지 않는다. 좌표에1/2 상수가 섞여 있다.

## 최초 계획 (진행 이력)

P1:450×43×40, Farbe, 뒷판 없음에서 밀도0·1·2·25·50·75·99·100. 변화가 생기는 경계는1% 전후를 추가한다.

P2:5행 기준에서 밀도에 따른 수직 병합과 인접 가로판 범위를 기록한다. 너비는 고정한다.

P3:최소폭과 칸 수가 바뀌는 폭 경계를 좁힌다. 높이·깊이·재질을 각각 따로 변경한다.

P4:왕복·변경 순서·새로고침·다른 시작 디자인을 비교한다. 학습에 사용하지 않은 너비/밀도/행 높이를 보류 검증한다.

## 공식 판단 원칙

템플릿·보간·폭 제한·행 병합·하드웨어 보정이 분리되어 있는지 조사한다. 공개 실행 스크립트의 정적 분석은 UI 관찰과 구분한다. 반올림된 칸 너비를 그대로 상수 배열로 넣어 특정 화면만 재현하지 않는다.

근거 사례 ID: 정식 사례 수집 중. 정확 내부 좌표, seed, 템플릿 선택 경계, 초기 디자인 영향: 미확인.

## 2026-10-13 정식 사례와 첫 수정

- `pattern-001`~`pattern-004`: 450cm, 1행 내경38, 깊이40, Farbe/Blau, 뒷판 없음. 밀도2→3.1(드래그 오차)→2→1→0→1→2. 마지막2와 최초2의 선반 ROI(89,503,666,65)를 디코딩한 RGB 129,870채널 모두 동일했다. 같은 세션의 이 복귀 실험만 통과했다. 칸은12개로 관찰했고 작은 너비 표기는 확신 없이 전사하지 않았다.
- `pattern-005`/`pattern-006`: 너비30cm에서 뒷판 Ohne→Mit. 한 개구부, 표시 내경26×38cm, 외경30×43cm. 뒷판 선택이 실제로 적용된다. 없음 상태에서 오른쪽 보강판이 보이며 정확 폭은 미측정이다.
- `pattern-007`: 수정 후 레퍼런스를 처음 측정한 너비37cm 보류 사례. 뒷판 있음, 한 개구부의 표시 내경33×38cm로 Befun 표시와 일치했다. 재질·카메라·조명 차이는 남는다.
- `reference-source-001`: 공개 JS 정적 분석. 현재 제품의 실제 실행 경로·설계표는 미확정이다.

좁은 폭(width≤43) 분기의 조기 반환 전에 행별 뒷판을 생성하도록 수정했다. 모든 행 뒷판 선택과 기존 hardwareLayers 계약을 적용한다. 30cm 화면 하나에 맞춘 좌표 대신 `내부폭=width−2×thickness`, 누적 행 높이로 계산한다. 기존 폭43 경계 자체는 이번에 검증하지 않았으며 유지했다. OFF 보강판 누락은 별도 미해결이다.

검증: 3개 기하 테스트(관찰 사례, 추가 폭31/37/43·깊이24/32/40·행 높이18/28/38 조합, 개별 hardware 행), 두 실제 화면 비교, 해당 파일 lint, 전체 build 통과. 보류 설정의 코드 테스트는 일반 기하 불변식 검사이며 전체 Tylko 일치 검증이 아니다.

## 공개 코드에서 확인한 생성기 구성

해당 번들에는 설계 데이터의 폭/밀도 구간으로 요소를 선택하고, 구간별 좌표 보간과 정수 반올림을 수행하는 생성기가 있다. 기준 좌표에 별도 이동량을 더하며 인접 행 좌표를 스냅하고 잠금 순서를 적용한다. 가로판은 끝점 쌍으로 분리 생성하고, 세로판은 두 행을 통과할 수 있다. Pattern·스냅·뒷판 행이 활성화된 경우 폭과 제품군별 표로 motion을 보정하는 분기도 있다.

따라서 이 후보 경로에서 정확한 재현에는 보간 함수뿐 아니라 설계표의 절점, 요소 조건, 행 스타일, 제품군, 보정표가 필요하다. 현재 sin 난수와 이동 계수만 바꿔 맞추는 접근은 근거가 없다. 다음 우선 작업은 실제 제품에 선택되는 공개 설계 데이터와 단위 변환을 확인하고 0/1/2% 사례 및 다행 병합으로 대조하는 것이다. 원본 번들 전체를 프로젝트에 복제하지 않았다.


## 2026-10-13 핵심 생성기 교체 — reference-source-002

### 확인한 사실과 구현

기존 VPN 연결 Chrome 제품 페이지가 로딩한 공개 `furniture_dna` 응답에서 Pattern container 2 → 기본 setup → grasshopper 12(`300_PATTERN_V13_t02`) 연결을 확인했다. 공개 수치 설계표 497개 요소와 뒷판 motion 보정표를 각각 `pattern-rules.json`, `pattern-motion.json`으로 정규화했다. 원본 실행 번들은 제품 코드에 복제하지 않았다.

독립 TypeScript 해석기는 다음 순서로 동작한다.

1. 폭·밀도 포함 구간, 요소 선행/제외 조건, 행 범위·레이아웃으로 요소를 선택한다.
2. 폭 절점의 기본 위치와 밀도 절점의 이동량을 두 단계 정수 반올림으로 보간한다. 화면 표시값을 좌표로 쓰지 않는다.
3. 인접 행의 30mm 미만 위치를 잠금 우선순위와 원래 요소 순서로 정렬한다.
4. 가로판은 정렬한 끝점 쌍으로 생성하고 세로판·보강판은 한 행 또는 두 행을 잇는다. 열린 가장자리도 보존한다.
5. Type02는 문이 없는 상태에서도 문 호환 레이아웃3으로 기본 구조를 생성하며, 넓은 칸을 추가 분할한다. 단순히 모든 넓은 칸을 반으로 나누지 않고 문 경계·분할 후보·최소 폭·강제 분할 조건을 평가한다.
6. 열린 레이아웃1의 보강판을 사용하고 기본 구조에 빠진 세로판을 40mm 근접 조건으로 보완한다.
7. 실제 패널에서 개구부를 도출하고 가로판이 없는 동일 폭의 인접 개구부를 병합한다. DimensionOverlay는 이 개구부를 사용한다.

확인된 Type02 물리 판두께는 **18mm**, 행 간격은200/300/400mm이며 실제 내경은182/282/382mm다. 이전 20mm 가정으로 계산한26×38cm는 화면 표시만 일치했으며 정확한 내부 좌표가 아니었다. 좁은30cm의 실제 내경은264×382mm로 수정했다.

### 검증 범위

`structure-fixtures.json`은 공개 레퍼런스 계산기를 임시 로컬 비교 대상으로 실행하여 독립 채집한 기대 좌표의 해시다. Befun 출력에서 기대값을 만들지 않았다. 가로판/세로판/보강판의 모든x/y 끝점과 중복 개수를 정렬하여0.001mm 단위로 비교한다.

- 개발 비교: 폭284.3/450, 밀도0/2/100,5행38cm.
- 구현 후 확장: 폭30/37/43/60/87/116/173/232/284.3/317/399/450 × 정수 밀도0~100 × 행 구성[38], [38,38,38,38,38], [18,28,38]. **3,636/3,636 수치 구조 일치.**
- 원본 수치 규칙에 없는 임의 난수·고정 화면 좌표를 사용하지 않는다.
- `node --test scripts/tylko-pattern/*.test.mjs`:5개 테스트 통과(3,636개 비교 포함). 변경 소스 eslint·tsc·production build 통과.
- 전체 lint: 기존 Scene.tsx any 오류1개와 경고15개로 실패. 다른 담당 잠금 파일은 수정하지 않았다.

이 검증은 공개 생성기의 열린 구조 수치 검증이다. 3,636개를 브라우저에서 하나씩 조작하거나 모든 옵션 조합을 확인한 것이 아니다. 패널 깊이·지지판 두께·발·접합부와 화면 픽셀 일치는 별도 검증이다.

### 남은 사항

- 뒷판은 기존 입력 계약을 유지해 개구부에 넣지만 병합 칸/부분 뒷판/보강판 제거의 레퍼런스 동치는 미확인. 뒷판 활성화 시 motion 보정표 연결은 구현했으나 전체 뒷판 조합 비교는 아직 하지 않았다.
- 문·서랍은 여전히 평균 Grid 간격을 사용하는 기존 하드웨어 경로. 실제 Pattern 개구부와 연결해야 하며 완료로 간주하지 않는다.
- 전역 store의20mm와 본체18mm, 발 높이, 외경 표시의0.2cm 차이가 남아 있다. 생산/가격 정책을 임의로 확정하지 않는다.
- Farbe 기준이며 Multiplexplatte Type0는 설계표/제품군 차이 재검증 필요. 모든 Befun 마감에 동일 Type02가 현재 적용되는 제한을 기록한다.
- 개구부 정수 표기는 현재 내림을 사용한다. 레퍼런스의 모든 정수 경계 표기와 UI 배치 검증은 남아 있다.
- 새로고침 시 URL의 원래 회색 Slant/하드웨어 디자인으로 복원됨을 관찰했다. 임시 UI 편집 전체가 URL에 저장되는 것은 아니다. 다른 초기 디자인/변경 순서 독립성은 아직 미확인이다.

실화면 재검증 `pattern-008`: 동일232cm·밀도0%·한 행38cm·깊이32cm·뒷판/문/서랍없음에서6칸, 표시 내경34/38/29/40/40/35cm가 양쪽 동일. 기존 VPN Chrome 탭 사용. 두PNG 저장. 색감·시점·발·라벨 외관은 불일치로 남긴다.
